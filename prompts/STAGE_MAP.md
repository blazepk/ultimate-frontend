# STAGE_MAP.md — old plan numbering ↔ STAGE_INPUTS.md numbering

Generated by Stage 2.6. `prompts/stage-NN.md` uses **`docs/STAGE_INPUTS.md`'s
numbering exclusively** — that is the frozen, authoritative scheme. The "old
plan" columns below exist only to help a human reader connect the new
prompts to the historical planning documents in `files/*.md`; they are not
executable and carry no authority. Per `docs/RULES.md`, no generated prompt
takes a package name, path, or type name from those files — intent only.

Two old-plan documents exist and disagree with each other in places:
`files/harness-build-plan-staged-prompts.md` (superseded) and
`files/harness-stages-3-onward-revised.md` (its replacement for stages 3+,
adding permission scopes and the DOCUMENTATION OUTPUT requirement). Where
they differ, the table below follows the revised one.

## Constraint C005 ownership

Per `docs/RECONCILIATION.md` §E.4: constraint C005 (`EVENTS_REQUIRE_JS`,
CONTRACTS §4.3 — contract declares ≥1 event ∧ `hydration = "none"`) is
**genuinely owned by STAGE_INPUTS.md Stage 2** (`packages/islands`,
`prompts/stage-02.md`), via `validateWithContracts`. It is outside the
240-tuple space checked by `@harness/contracts`' `checkConstraints` because
it depends on `IslandContract` event declarations, which
`@harness/contracts` never loads. This was correctly deferred by the
executed "Stage 2" prompt (the one that produced `packages/flags/`) — that
report's citation of "Stage 2" was a numbering-scheme mismatch, not a
substance error (`docs/decisions/02-reconciliation.md` finding 2).

## INPUTS corrections made

Two corrections to what a literal translation of `docs/STAGE_INPUTS.md`
would have produced, both recorded in the affected prompt's own `requires`
block and here for visibility:

1. **`prompts/stage-01.md`** additionally lists the four already-migrated
   `packages/contracts/src/*.ts` files (`types.ts`, `constraints.ts`,
   `resolve.ts`, `budget.ts`) and `docs/PUBLIC_API.md` in `requires`, beyond
   STAGE_INPUTS.md's bare `docs/CONTRACTS.md` for Stage 1. Reason: this
   package is no longer greenfield — the Stage 2.5 recovery already built
   part of it, and a stage that can't see what already exists would
   duplicate or conflict with it. STAGE_INPUTS.md was written before that
   partial build existed.
2. **Every generated prompt** lists `docs/RULES.md` in `requires` (the
   amended preamble) and, where relevant, `docs/PUBLIC_API.md` (for real
   package names and exports maps) — neither exists in STAGE_INPUTS.md's
   "universal set" because both postdate it. Both are necessary for every
   stage to resolve its own package name and avoid re-deriving the
   preamble.

No stage plainly needed a file that is *entirely* missing from its
STAGE_INPUTS.md row (unlike the original Stage 2, which needed
`docs/REWARD.md` and didn't have it) — Stages 6, 7, and 8 already list
`docs/REWARD.md` in STAGE_INPUTS.md, and that carried through unchanged.
